# 镜头表

**一句话**：一镜一行。**创作在这里结束。**

## 启用 / 不启用

> 这一节是硬约束。**不是建议。**

| | |
|---|---|
| ✅ **加载** | 本工序 `jingtou`（需要上游产物就直接读文件，不用加载别的 skill） |
| ✅ **画面来源** | **视频模型生成**（Wan 3.0 / Seedance 2.0·2.5）——**这是本套唯一的出片方式** |
| ❌ **不用代码合成** | HTML / CSS / Canvas / SVG / Remotion / After Effects / 截图拼接 / 模板套用——**画面一律不许这么做** |
| ✅ **用工具** | 读文件 · 写文件（**只写 03-镜头表.md**） |
| ❌ **不加载** | `hyperframes` 全家桶（core/animation/cli/studio/creative/keyframes/registry/audio）、`general-video`、`motion-graphics`、`slideshow`、`faceless-explainer`、`product-launch-video`、`media-use`、`video-shotcraft`、`remotion-*` |
| ❌ **不跑命令** | `npx hyperframes …`、`pnpm hyperframes …`、`hyperframes init`、`hyperframes render`、`remotion …`、任何渲染 / 发布 / 上传命令 |
| ❌ **不建结构** | 不建 `.hyperframes/`、不建 `compositions/`、不写 `index.html`、不写 `package.json`、不跑 `init` |
| ❌ **不碰接口** | 不生图、不生视频、不跑 TTS |
| ❌ **不写别的文件** | 除 `03-镜头表.md` 外，不写任何文件 |

### 为什么写这么死

`hyperframes` 自称「任何视频请求的强制入口」，它全家桶加起来二十多个 skill、
一套 CLI、一套项目脚手架。**一旦它启动，就会建目录、写 `index.html`、跑渲染**——
那时候再喊停，已经写了一堆不该有的东西。

**所以不是「用错了再改」，是「压根不许启动」。**

> **这一节只能约束本工序自己。** 拦不住 `hyperframes` 被别处触发——
> 那要看它的 description 和项目配置。真要压死，在项目级 `CLAUDE.md` 里写一次，或者在这个项目里禁用它。


### 只做一件事

本工序只负责出 `03-镜头表.md` 这一份东西。
**不合成、不渲染、不配乐、不发布。** 那些都不在这里。

## 产物

写到 `<项目>/03-镜头表.md`，一场一张表。

写完说一句：「这一步完了。下一步**加载 `sucai`**，用《素材》。」

## 进门前
- **读 `01-剧本.md` 文件头的「画幅」**——画幅决定「距」的刻度（竖屏的 4 和横屏的 4 不是一个距离）
- **读 `02-定戏.md` 每节末尾的「选定：」那一行**——那就是这一场的讲法
- 如果那一行不在，回 `dingxi` 补，别自己从三条里挑

## 不做什么
- 不写提示词
- **不写**模型名、不写分片时长上限；**每镜的时长必须写**（这是两回事）
- 不分片（→《生成》）
- 不改讲法

## 五站

1. **四数**：距离 / 时长 / 看眼 / 信息差
2. **存在理由**：六类之一
3. **上镜留下的问题**
4. **剪接点**：类型 + 机位夹角 + 屏幕方向 + **接什么**（这一镜接上一镜的哪一样）
5. **回读**：整表读一遍，看有没有浮出一条规则

> **这一站只管到「镜头」为止。** 怎么分段、段和段怎么接，是《生成》的事——
> 那时候才知道单段上限，才知道哪几镜落在同一次生成里。

## 四数

| 数 | 范围 | 决定 |
|---|---|---|
| 距离 | 1（看不清脸）→ 5（睫毛） | 观众被允许靠多近 |
| 时长 | 秒 | 观众被迫看多久 |
| 看眼 | 是 / 否 / — | 观众能不能确认她在想什么 |
| 信息差 | 观众多 / 一样 / 少 | 谁先看见真相 |

## 存在理由六类

交代空间 / 制造异常 / 提供证据 / 转移注意 / 收放情绪 / 节奏重音

**写不出理由的镜头，删掉。**

多余镜头在技术上完全合法，没有任何检查能发现它——只有这一问能。

## 第 5 站

回读全表，看有没有浮出一条规则（「全片只有一次正脸」这类）。

**规则从哪一列浮出都可能**——距离、看眼、信息差、时长。别默认只看眼。

**不要提前设计规则。** 那是你想的，不是表长出来的。表长出来的才立得住。

## 表格格式（脚本要用）

| 镜号 | 距 | 时长 | 看眼 | 信息差 | 存在理由 | 剪接点 | 接 | 画面 |
|---|---|---|---|---|---|---|---|---|

- 「时长」写 `4.0` 或 `4s`，别写「四秒」
- 「画面」写物件名（碗 / 糖纸 / 相框），脚本靠它扫素材覆盖
- **「接」写这一镜接上一镜的什么**（见下节）
- **镜号带 ★ 的，是不可省镜头**（`S3-05★`）

### 「接」这一列写什么

**五样里挑一样，必须挑得出来：**

| 接什么 | 例 |
|---|---|
| **动作** | 上一镜他抬手 → 这一镜刀已经离鞘 |
| **物件** | 上一镜是碗 → 这一镜是碗沿上的豁口 |
| **声音** | 上一镜雨声起 → 这一镜先听见雨，再看见人 |
| **视线** | 上一镜他看向门 → 这一镜是门外 |
| **位置** | 上一镜他在左半画 → 这一镜仍在左半画 |

**五样都没有，就是跳切。** 不是「剪得紧」，是断了。


## 闸被跳过时，必须登记

用户催进度（「直接生成」「别问了」「你剪吧」）时，**闸可以被跳过，但必须留痕**：

```
⏭ 跳过：★ 没标
   代价：（写清会因为这一跳丢掉什么）
   决定人：用户
```

**写在本工序产物文件的「跳过记录」一节里**——不是写进别人的文件，也不是只在对话里说一句。

**三件事缺一不可**：跳过了什么 / 代价是什么 / 谁决定的。

**没有登记的跳过 = 事故。** 因为下一轮没人知道哪里漏了。

## 跳切自检（写完表必做一遍）

手指沿着表往下走，每两行之间问一句：**「接上了吗？」**

| 症状 | 说明 |
|---|---|
| 相邻两镜的「接」都是空的 | 跳切，补一镜或重写 |
| 一整场没有一镜「接声音」 | 全片都是画面切画面，会显得干 |
| 一场里「接动作」超过一半 | 全在动，观众没有喘气的地方 |

**每场至少有一处「接视线」或「接声音」**——那是让观众跟得上换气的地方。

## 出门判定

- [ ] 每行写得出存在理由？
- [ ] **全片时长和 `01-剧本.md` 的估算差在 15% 以内**？（估算是粗的，别拿 ±5% 卡它；差太多说明分场有问题，回 `juben`）
- [ ] **每一镜的「接」都填了**（五样之一）？
- [ ] 每场至少有一处「接视线」或「接声音」？
- [ ] 没有连续 4 个镜头时长差都在 20% 以内？
- [ ] 回读时有没有浮出规则？

**逐条打勾，列出没通过的，停下等人确认。**
