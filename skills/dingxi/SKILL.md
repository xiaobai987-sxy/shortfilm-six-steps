# 定戏

**一句话**：先看清楚这场戏，再决定用什么讲法。**这一步不碰镜头。**

## 启用 / 不启用

> 这一节是硬约束。**不是建议。**

| | |
|---|---|
| ✅ **加载** | 本工序 `dingxi`（需要上游产物就直接读文件，不用加载别的 skill） |
| ✅ **画面来源** | **视频模型生成**（Wan 3.0 / Seedance 2.0·2.5）——**这是本套唯一的出片方式** |
| ❌ **不用代码合成** | HTML / CSS / Canvas / SVG / Remotion / After Effects / 截图拼接 / 模板套用——**画面一律不许这么做** |
| ✅ **用工具** | 读文件 · 写文件（**只写 02-定戏.md**） |
| ❌ **不加载** | `hyperframes` 全家桶（core/animation/cli/studio/creative/keyframes/registry/audio）、`general-video`、`motion-graphics`、`slideshow`、`faceless-explainer`、`product-launch-video`、`media-use`、`video-shotcraft`、`remotion-*` |
| ❌ **不跑命令** | `npx hyperframes …`、`pnpm hyperframes …`、`hyperframes init`、`hyperframes render`、`remotion …`、任何渲染 / 发布 / 上传命令 |
| ❌ **不建结构** | 不建 `.hyperframes/`、不建 `compositions/`、不写 `index.html`、不写 `package.json`、不跑 `init` |
| ❌ **不碰接口** | 不生图、不生视频、不跑 TTS |
| ❌ **不写别的文件** | 除 `02-定戏.md` 外，不写任何文件 |

### 为什么写这么死

`hyperframes` 自称「任何视频请求的强制入口」，它全家桶加起来二十多个 skill、
一套 CLI、一套项目脚手架。**一旦它启动，就会建目录、写 `index.html`、跑渲染**——
那时候再喊停，已经写了一堆不该有的东西。

**所以不是「用错了再改」，是「压根不许启动」。**

> **这一节只能约束本工序自己。** 拦不住 `hyperframes` 被别处触发——
> 那要看它的 description 和项目配置。真要压死，在项目级 `CLAUDE.md` 里写一次，或者在这个项目里禁用它。


### 只做一件事

本工序只负责出 `02-定戏.md` 这一份东西。
**不合成、不渲染、不配乐、不发布。** 那些都不在这里。

## 产物

写到 `<项目>/02-定戏.md`，**每场一节**，节标题用场号（`## S3`）。

写完说一句：「这一步完了。下一步**加载 `jingtou`**，用《镜头表》排 S3。」

## 进门前
- 剧本已定，这场戏的边界清楚（从哪进、在哪出）
- **先读 `01-剧本.md` 的设定集**：这一场的人「想要什么 / 怕什么 / 藏什么」

> 三问的第 2 问（哪一刻最疼）答不出来，八成是因为设定集里「怕」和「藏」没写。

## 不做什么
- 不排镜头（→《镜头表》）
- 不写提示词
- 不决定时长和分片

## 三站

### 1 三问

1. 观众进来知道什么，出去知道什么？
2. 哪一刻最疼？那一刻**看到什么、看不到什么**？
3. 只能用一个镜头讲完这一场，你选哪个？

**第三问最狠。** 它逼出核心镜头，而不是把时间平均分给六个镜头。

**第二问必须有「看不到什么」。** 只写「看到什么」，那只是画面清单，不是设计。

### 2 三条讲法（有时只要一条）

每条四行：

- 一句话讲法
- 这一版赌什么
- 这一版牺牲什么
- 观众记住哪一帧

#### 什么时候不用三条

| 这一场是什么 | 写几条 |
|---|---|
| **有转折**（人物改变了主意 / 观众改变了判断） | 三条 |
| **过场**（只是把人从 A 送到 B） | **一条**，写清为什么不值得选 |
| **短于 6 秒** | **一条**，写清为什么不值得选 |
| 纯动作 / 纯信息 | 两条够 |

**「简单」不能当理由。** 要写的是：

> 「这一场没有选择余地：门必须开，他必须进去。差别只在快慢。」

**写不出这句，就还是得写三条。**

#### 「三条真的不同」怎么判

**不能靠感觉，看三样里有没有变：**

| 变什么 | 意思 |
|---|---|
| **观众先看见谁** | 先看见他，还是先看见刀 |
| **观众被放在哪** | 站在他身后，还是站在对面 |
| **什么时候给答案** | 一开始就给你，还是最后才给 |

**三样全一样，就是同一条讲法的三种措辞。** 那不是三条。

### 3 选一条，写选择理由

理由只有一个合格写法：

> **「因为它放弃了 X，而这一场不需要 X。」**

```
✗ 因为 A 更有张力
✗ 因为 A 更好看
✓ 因为 A 放弃了「看见他的脸」，而这一场不需要观众确认他在想什么
```

**说不出「放弃了什么」，就是没选，只是挑了个顺眼的。**


## 闸被跳过时，必须登记

用户催进度（「直接生成」「别问了」「你剪吧」）时，**闸可以被跳过，但必须留痕**：

```
⏭ 跳过：三条讲法没逐场确认
   代价：（写清会因为这一跳丢掉什么）
   决定人：用户
```

**写在本工序产物文件的「跳过记录」一节里**——不是写进别人的文件，也不是只在对话里说一句。

**三件事缺一不可**：跳过了什么 / 代价是什么 / 谁决定的。

**没有登记的跳过 = 事故。** 因为下一轮没人知道哪里漏了。

## 出门判定

- [ ] 三条在「怎么讲」上真的不同（不是换景别）？
- [ ] 每条都写得出「牺牲什么」？
- [ ] 第二问里有「看不到什么」？
- [ ] **写了三条的场**：三条里至少变了一样（先看见谁 / 放在哪 / 什么时候给答案）？
      **只写一条的场**：写清了「为什么没有选择余地」？
- [ ] **这一节末尾有「选定：」和「核心镜头：」两行**？
- [ ] 选择理由写的是「放弃了什么」，不是「更好看」？

**写不出「牺牲什么」，就是三条一样。** 真不一样的三条，你必须放弃点东西。

**逐条打勾，列出没通过的，停下等人确认。**

## 想不出来就如实说，不硬凑

三条写不出区别，说明这场还没读懂——回第一站，别硬选。

## 每一场都要停下来

**不要六场一口气做完。**

每场写完 02-定戏.md 的一节，**停下，把三条（或一条）讲法摆给用户，等他选。**

```
S1 定完 → 停（等选）
S2 定完 → 停（等选）
...
```

**六场一起给，用户只能整体点头或整体摇头**——那时候已经写完了，改不动了。

## 每场末尾必须留两行（给下一工序的契约）

`02-定戏.md` 每一节的最后，**必须是这样两行**：

```
选定：账本立在刀和他脖子之间——纸挡着铁（一句话讲法原样抄）
核心镜头：血页上那滴被指头压出来的印（写画面，不写镜号）
```

**不许写镜号。** 这时候镜头表还没排，S3-05 不存在——写了，`jingtou` 就只能照抄一个假编号。
镜号由 `jingtou` 编号，它自己决定哪一镜是核心并标 ★。

**没有这两行，镜头表就只能自己猜你选了哪条。**

`jingtou` 读文件时，只读这两行。

## 旁支

**按「这一场有没有转折」分，不按片种分。**

| 场型 | 怎么简化 |
|---|---|
| 产品片 / 口播片（没有「最疼一刻」） | 第一问 + 一条讲法 |
| **纯过场**（人从 A 到 B） | 第一问 + 一条讲法，重点写「怎么走得不像废镜头」 |
| **纯动作场** | 三问照做，但第 2 问改成「哪一下最狠」，第 3 问改成「哪一下必须看见」 |
| **纯信息场**（念账、交代） | 第 2 问改「观众哪一刻会走神」，第 3 问改「拿什么抓住他」 |

**三问的形式可以变，但必须有「看到一个、看不到一个」这个结构。**

## 下一步

选定的那条交给 `jingtou`（加载它）。
